Expected value E(X): the long-run average

The expected value (mean) of a random variable is a single number summarizing "where the distribution is centered" — the long-run average you'd get if you repeated the experiment over and over and averaged all the results.

E(X) = Σₓ x·P(x)  (discrete)     E(X) = ∫₋∞^∞ x·f(x)dx  (continuous)
xa possible value of X
P(x) / f(x)how likely/dense that value is
the sum/integrala weighted average — each value contributes in proportion to how likely it is
Analogy E(X) is exactly like a weighted grade average, where each possible outcome is a "grade" and its probability is its "weight" (like credit hours). A value that almost never happens barely moves the average; a value that happens most of the time dominates it — same logic as a 4-credit module counting more toward your GPA than a 1-credit module.

Three algebra shortcuts that save huge amounts of work — memorize these, they get used constantly:

E(c) = c    E(cX) = cE(X)    E(aX+b) = aE(X)+b

In words: a constant's "average" is just itself; scaling X scales its average by the same factor; shifting X shifts its average by the same amount. This is just common sense written as algebra — if everyone's salary doubles, the AVERAGE salary also exactly doubles.

Variance: how spread out the values are

Two distributions can have the identical mean but look completely different — e.g. test scores {47,48,49,51,52,53} vs {0,1,2,98,99,100} both average to 50, but one is tightly clustered and the other is wildly spread out. Variance captures exactly this "how spread out" idea, by measuring the average squared distance from the mean.

Var(X) = E[(X−μ)²] = E(X²) − [E(X)]²
μ = E(X)the mean, computed first
(X−μ)²squared so that being-too-low and being-too-high both count as "spread," rather than cancelling out
E(X²) − [E(X)]²the shortcut formula — in practice ALWAYS use this instead of expanding (X−μ)² by hand; just compute E(X²) and E(X) separately, then subtract

Standard deviation σ = √Var(X) is just variance brought back to the original units (variance is in "squared units," which is often awkward to interpret — e.g. "squared hours" — so σ converts it back to plain hours/grams/etc).

Var(c) = 0    Var(cX) = c²Var(X)    Var(aX+b) = a²Var(X)

Notice: adding a constant b does NOT change the variance (shifting everything left/right doesn't change how spread out it is), but scaling by a DOES — and the scale factor gets squared, because variance itself is already built from squared distances.

Worked example: X takes values −1, 0, 1, each with probability 1/3. Find mean/variance of X and of 2X−1.

  • E(X) = (−1)(1/3) + (0)(1/3) + (1)(1/3) = 0.
  • E(X²) = (1)(1/3) + (0)(1/3) + (1)(1/3) = 2/3.
  • Var(X) = E(X²) − [E(X)]² = 2/3 − 0 = 2/3.
  • Using the shortcuts: E(2X−1) = 2E(X)−1 = 2(0)−1 = −1. Var(2X−1) = 2²Var(X) = 4(2/3) = 8/3.

    • The normal distribution: the classic bell curve

    The normal distribution is the single most important continuous distribution — heights, weights, measurement errors, and countless naturally-occurring quantities cluster around an average in this symmetric, bell-shaped way.

    f(x) = (1/(σ√(2π))) · exp[ −(x−μ)²/(2σ²) ],  −∞<x<∞     written X ∼ N(μ, σ²)
    μthe mean — sets WHERE the peak of the bell sits
    σ²the variance — sets HOW WIDE/flat the bell is (bigger σ² → shorter, wider bell)

    You are never expected to integrate this formula by hand. Instead, every normal question is solved by converting to the standard normal Z ∼ N(0,1) (mean 0, variance 1) and reading probabilities off the standard normal table (Table A1), using φ(z) = P(Z≤z):

    Z = (X − μ)/σ       P(a ≤ X ≤ b) = φ((b−μ)/σ) − φ((a−μ)/σ)
    Analogy Standardizing is like converting every currency to USD before comparing prices. X could be measured in weeks, grams, or months — completely different scales — but Z always answers the same question in the same units: "how many standard deviations away from the mean am I?" Once everything is in Z-units, one single table (Table A1) works for every possible normal problem, no matter what μ and σ happen to be.

    Worked example: battery life X ∼ N(3, 0.5²) weeks (mean 3 weeks, sd 0.5 weeks).

  • P(X<2.3): standardize, z=(2.3−3)/0.5=−1.4, so P = φ(−1.4) = 0.0808.
  • P(X>4): z=(4−3)/0.5=2, so P = 1−φ(2) = 1−0.9772 = 0.0228 (2.28%).
  • "Find α such that P(X≥α)≥0.8" (find the value 80% of batteries last beyond): work backwards — need φ((α−3)/0.5) ≤ 0.2, look up in the table which z gives φ(z)≈0.2 (z≈−0.84), then solve (α−3)/0.5 = −0.84 → α = 2.58 weeks.

    • That last step — "given a probability, find the boundary value" — is the reverse-lookup direction and comes up often: instead of looking up φ(z) from a given z, you scan the table for the probability you want and read off z, THEN convert that z back to an X value using X = μ + zσ.

    The Poisson distribution: counting random arrivals

    The Poisson distribution is a discrete distribution used whenever you're counting how many random, independent events happen in a fixed window of time or space — customer arrivals, phone calls, machine breakdowns, flaws per square metre.

    P(X=k) = e^(−λ)λᵏ/k!,  k=0,1,2,…     written X ∼ P(λ)       μ = λ,  σ² = λ
    λthe average rate of events over the SAME window you're measuring — e.g. "2 customers per hour" if you're computing hourly probabilities
    kthe specific count you're asking about
    e^(−λ)a normalizing constant baked into the formula — you don't need to understand where it comes from, just that it's always there

    One property that trips people up constantly: λ must match the time window in the question. If the rate is given per year but the question asks about a 4-month period, you must first rescale λ = (rate)×(fraction of the year), e.g. λ_year=4.2 → λ_4-months = 4.2×(4/12) = 1.4.

    Worked example: customers arrive at a shop at λ=2 per hour.

  • P(no customers) = P(X=0) = e^(−2)(2⁰)/0! = e^(−2) = 0.135.
  • P(at most 1) = P(X=0)+P(X=1) = e^(−2)(1+2) = 0.406.
  • P(more than 3) = 1 − P(X≤3) = 1 − [P(0)+P(1)+P(2)+P(3)] = 0.143 — always easier to compute "1 minus the complement" than add up an open-ended infinite tail directly.

    • The binomial distribution: counting successes in a fixed number of tries

    The binomial distribution models the number of "successes" out of a FIXED number n of independent yes/no trials, each with the same success probability p. It's discrete.

    P(X=k) = C(n,k) pᵏ(1−p)ⁿ⁻ᵏ,  k=0,1,…,n     written X ∼ B(n,p)       μ = np,  σ² = np(1−p)
    nthe fixed number of trials (this is what makes it binomial rather than Poisson — Poisson has no fixed "n," it just counts arrivals over a window)
    pprobability of "success" on any ONE trial, same every time
    C(n,k) = n!/(k!(n−k)!)the number of different ways to choose WHICH k of the n trials were the successes
    Analogy Binomial vs Poisson is "how many heads in exactly 12 coin flips" (binomial — a fixed, known number of tries) vs "how many customers walk in during the next hour" (Poisson — no fixed cap, could in principle be any non-negative number, you're just counting arrivals over a stretch of time).

    Worked example: 5% of durians in an orchard are tasteless rejects. In a sample of 12, X ∼ B(12, 0.05).

    P(exactly 2 rejects) = C(12,2)(0.05)²(0.95)¹⁰ = 0.099
    P(at most 2) = P(0)+P(1)+P(2) = 0.54+0.341+0.099 = 0.98
    P(at least 2) = 1 − [P(0)+P(1)] = 1 − 0.881 = 0.12

    You'll come back to the binomial distribution again next week, where — for LARGE n — it can be approximated by the normal distribution instead of computing dozens of individual C(n,k) terms by hand.

    Q1
    Tests: E(X), Var(X) for discrete and continuous r.v.'s, plus the E(aX+b)/Var(aX+b) shortcuts

    (a) X = number of 5-kg lots ordered by a customer from a 100 kg stock, with pmf P(1)=0.2, P(2)=0.4, P(3)=0.3, P(4)=0.1. Find E(X), Var(X), and hence the expected kg left and its variance after the order ships. (b) X has density f(x)=cx² for 0≤x≤1. Find c, then the mean/variance of X and X², and hence E(2X+1), Var(2X+1), E(3−2X²), Var(3−2X²).

    Answer

    Part (a) Step 1 — apply the discrete formulas directly.

    E(X) = (1)(0.2)+(2)(0.4)+(3)(0.3)+(4)(0.1) = 2.3 lots
    E(X²) = (1)(0.2)+(4)(0.4)+(9)(0.3)+(16)(0.1) = 6.1
    Var(X) = 6.1 − 2.3² = 6.1 − 5.29 = 0.81

    Step 2 — kilograms LEFT is a linear transformation of X: (kg left) = 100 − 5X (each lot removes 5 kg). Apply the shortcuts directly instead of recomputing from scratch:

    E(100−5X) = 100 − 5(2.3) = 88.5 kg
    Var(100−5X) = (−5)²Var(X) = 25(0.81) = 20.25

    Part (b) Step 1 — find c using the "total area = 1" rule. ∫₀¹ cx² dx = c/3 = 1 ⇒ c=3.

    Step 2 — mean and variance of X, via the continuous formulas.

    E(X) = ∫₀¹ x(3x²)dx = 3/4    E(X²) = ∫₀¹ x²(3x²)dx = 3/5
    Var(X) = 3/5 − (3/4)² = 3/80

    Step 3 — mean and variance of X², treating Y=X² as its own r.v. and using E[g(X)]=∫g(x)f(x)dx. We already have E(X²)=3/5 (this IS "E(Y)"); we additionally need E(X⁴)=E(Y²):

    E(X⁴) = ∫₀¹ x⁴(3x²)dx = 3/7
    Var(X²) = E(X⁴) − [E(X²)]² = 3/7 − (3/5)² = 12/175

    Step 4 — apply the linear-transform shortcuts one more time, now treating X² itself as the base r.v.

    E(2X+1) = 2(3/4)+1 = 5/2    Var(2X+1) = 4(3/80) = 3/20
    E(3−2X²) = 3−2(3/5) = 9/5    Var(3−2X²) = 4(12/175) = 48/175

    I recomputed every fraction in part (b) exactly using Python's Fraction class — all values above are exact, not rounded, and match the shortcut-formula approach.

    Q2
    Tests: standardizing a normal r.v. to Z, and the reverse-lookup (probability → boundary value) direction

    Watch lifetimes are normal with mean 28 months, sd 5 months. (a) If refunds are given for failures within 2 years (24 months), what % of watches get refunded? (b) If Timeless wants to refund no more than 12% of watches, how long (to the nearest month) should the guarantee period be?

    Answer

    Step 1(a) — "refunded" means the watch failed before the guarantee period ends, i.e. we want P(X<24) where X∼N(28,5²). Standardize first:

    z = (24−28)/5 = −0.8    P(X<24) = φ(−0.8) ≈ 0.2119 → 21.19%

    Step 2(b) — this is the REVERSE direction: we're given a target probability (0.12) and need to find the boundary month t. We want the guarantee period t such that P(X<t) = 0.12 (no more than 12% fail within the guarantee window).

  • Convert the target probability to a z-score: find z such that φ(z)=0.12. Scanning Table A1 (or using its inverse), z ≈ −1.175.
  • Convert that z back into an actual month value using X = μ + zσ: t = 28 + (−1.175)(5) ≈ 22.1 months.
  • Round to the nearest month (and round DOWN if you must be conservative about not exceeding 12% — here it rounds to 22 either way): t ≈ 22 months.

    • I verified both parts numerically using scipy.stats.norm — 21.19% and 22.13 months (rounds to 22), matching the answer key exactly.

    Q3
    Tests: Poisson pmf, and using the complement to avoid an infinite tail sum

    Customer arrivals at a POSB cashier follow a Poisson distribution with mean 1 person per minute. What's the probability that in a given minute, arrivals will be 3 or more? Would you tell the bank manager that arrivals will rarely exceed 3 per minute?

    Answer

    Step 1 — identify λ. λ=1 (already given per-minute, matching the question's per-minute window — no rescaling needed this time). X ∼ P(1).

    Step 2 — "3 or more" is an infinite tail (3,4,5,6,…), so use the complement instead of summing forever.

    P(X≥3) = 1 − P(X≤2) = 1 − [P(0)+P(1)+P(2)]
    = 1 − e^(−1)[1 + 1 + 1/2] = 1 − e^(−1)(2.5) ≈ 0.0803

    I verified this using scipy.stats.poisson.cdf — 0.08030, matching the answer key.

    Interpreting the number for the manager: about 8% of minutes will see 3+ arrivals — that's roughly 1 in every 12 minutes, which is NOT "rare" in any everyday sense (it'll happen several times per hour). So no, you should NOT tell the manager arrivals will rarely exceed 3 — "rarely" (usually meant as under ~1–5%) doesn't match an 8% chance, this is a genuinely common occurrence the bank should staff for.

    ✍️ Write This Down

    Copy these into your own notes:

    • E(X): weighted average of values by probability. Var(X)=E(X²)−[E(X)]² — always use this shortcut, never expand (X−μ)² by hand.
    • Linear transform shortcuts: E(aX+b)=aE(X)+b, Var(aX+b)=a²Var(X) — shifting (b) never changes spread, scaling (a) changes spread by a², not a.
    • Normal X∼N(μ,σ²): standardize with Z=(X−μ)/σ before doing anything else. P(a≤X≤b)=φ((b−μ)/σ)−φ((a−μ)/σ). For "find the value given a probability" questions, look up z from the target probability FIRST, then convert back via X=μ+zσ.
    • Poisson X∼P(λ): P(X=k)=e^(−λ)λᵏ/k!, mean=variance=λ. Always match λ's time/space window to the question's window — rescale proportionally if they differ.
    • Binomial X∼B(n,p): P(X=k)=C(n,k)pᵏ(1−p)ⁿ⁻ᵏ, mean=np, variance=np(1−p). Fixed number of trials n is the key giveaway vs Poisson (no fixed n).
    • For any "at least / more than" tail probability, compute 1 − P(complement) instead of summing an open-ended or long list of terms directly.

    👁️ Visualize It

    The normal curve, standardized: shading shows the battery-life example from the slides — P(X<2.3 weeks) — after converting to Z. The shaded area under the curve to the left of z=−1.4 IS the probability, exactly the same "area = probability" idea from continuous r.v.'s back in Week 3.

    Every normal probability question is really just this same picture with a different shaded region: "less than" shades the left tail, "greater than" shades the right tail, "between a and b" shades a middle strip, and the reverse-lookup direction (part (c)/(b) style questions) starts from a KNOWN shaded area and asks you to find where the boundary line must be.

    A rule of thumb worth sketching from memory

    • The classic "68–95–99.7 rule": about 68% of a normal distribution's values fall within 1σ of μ, about 95% within 2σ, about 99.7% within 3σ. It's not a formula you'll be tested on directly, but it's an excellent gut-check — if your calculated probability for "within 1 sd of the mean" comes out as, say, 0.3 instead of ~0.68, you've likely made a sign or z-score error somewhere.
