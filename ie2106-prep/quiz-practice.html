📘 Tutorial 8 — interpolation & fixed-point iteration

Q1 · Tut 8

Newton's divided-difference polynomial through (1, 2), (2, 3), (4, 11). Evaluate p(3) (4 d.p.).

Try it yourself first, then reveal the full solution
Answer: 6.0000

What it’s asking: You have three measured points. Build the one smooth parabola that passes through all of them, then read its height at x = 3 — a spot between the known points x = 2 and x = 4 where you have no measurement.

Steps needed: (1) work out the slopes between neighbouring points; (2) work out how much those slopes change; (3) assemble Newton’s polynomial; (4) plug in x = 3.

p(x) = f[x0] + f[x0,x1](x−x0) + f[x0,x1,x2](x−x0)(x−x1)
f[x0]the height at the first node (here 2) — the starting level
f[x0,x1]first divided difference = (f1−f0)/(x1−x0) = the slope of the straight line joining two points
f[x0,x1,x2]second divided difference = (f[x1,x2]−f[x0,x1])/(x2−x0) = how much the slope changes = the bend the parabola needs
(x−x0)…switch factors that are zero at the earlier nodes, so each new term adds bend without disturbing points already matched

It builds a polynomial that hits every data point exactly, so you can estimate values between measurements. Works for any distinct x-values (they need not be evenly spaced), and a new data point only adds one more term.

  1. Slopes: f[1,2] = (3−2)/(2−1) = 1 and f[2,4] = (11−3)/(4−2) = 4.
  2. Change in slope: f[1,2,4] = (4−1)/(4−1) = 1. The denominator is x2−x0 = 4−1 (the two outer nodes), not 4−2.
  3. p(x) = 2 + 1(x−1) + 1(x−1)(x−2).
  4. p(3) = 2 + 1(2) + 1(2)(1) = 2 + 2 + 2 = 6.0000.

What it means / check: expanded, p(x) = x²−2x+3, which gives 2, 3, 11 at x = 1, 2, 4 (so it really passes through the data) and 6 at x = 3 — sensibly between 3 (at x=2) and 11 (at x=4).

Common mistakes: dividing the second difference by (x2−x1) instead of (x2−x0); flipping one subtraction (one sign slip wrecks every later number); using (x−x1)(x−x2) in the last term instead of the first two nodes.

Q2 · Tut 8

Linear/quadratic interpolation error: f(x)=ln x is interpolated at nodes 1, 2, 3. Give an upper bound for |f(1.5) − p(1.5)| (4 d.p.).

Try it yourself first, then reveal the full solution
Answer: 0.1250

What it’s asking: Replace ln x by the parabola through x = 1, 2, 3. At x = 1.5, how wrong could the parabola possibly be? You are asked for a guaranteed ceiling on the error, not the exact error.

Steps needed: (1) differentiate ln x three times; (2) find the biggest value of that third derivative on [1, 3]; (3) evaluate the node product at x = 1.5; (4) combine with 1/3!.

|f(x) − p(x)| ≤ [ M / (n+1)! ] · |(x−x0)(x−x1)…(x−xn)|
ndegree of the interpolating polynomial = number of nodes minus 1 (three nodes ⇒ n = 2)
Mthe largest |f(n+1)(ξ)| anywhere on the interval containing the nodes and x — the “worst-case curviness” the parabola cannot capture
(n+1)!3! = 6, the factorial that shrinks the error when you use more nodes
productdistance from x to every node, multiplied — it is zero at a node (no error there) and grows as you move away

Why we need it: in real life you do not know the true f, so you need a promise of how far the interpolant can be off. Valid when f has n+1 continuous derivatives on the interval. Since the unknown point ξ could be anywhere, you must use the maximum of the derivative, not its value at x.

  1. f = ln x, f′ = 1/x, f″ = −1/x², f‴ = 2/x³.
  2. 2/x³ shrinks as x grows, so on [1,3] its maximum is at x = 1: M = 2. (At x = 1.5 it is only 0.5926; using that would not be a guarantee.)
  3. Product at 1.5: (0.5)(−0.5)(−1.5) = +0.375.
  4. Bound = (2/6)(0.375) = 0.1250.

What it means: the parabola is guaranteed to be within 0.125 of ln 1.5. The actual error is |0.405465 − 0.382534| = 0.022931, comfortably inside the bound — bounds are pessimistic because they assume the worst curvature everywhere.

Common mistakes: dividing by 2! instead of 3! (three nodes means (n+1)! = 3!); evaluating f‴ at x = 1.5 instead of taking its maximum; using f″ instead of f‴; forgetting one of the three factors in the product.

Q3 · Tut 8

Fixed-point iteration xn+1=cos(xn), x0=1. Give x3 (4 d.p.).

Try it yourself first, then reveal the full solution
Answer: 0.6543

What it’s asking: Start from the guess 1, feed it into cos, take the output as the next guess, and repeat. Report the guess after three rounds.

Steps needed: (1) switch the calculator to radians; (2) compute x1, x2, x3 in turn, keeping 6 d.p.; (3) round only the last one.

xn+1 = g(xn) = cos(xn)    (converges to x* with x* = g(x*) if |g′(x*)| < 1)
g(x)the rule that turns one guess into the next (here, cosine)
xnthe current guess; x0 = 1 is the starting guess, so x3 is the output of the third application
x*the fixed point: the number that cos leaves unchanged, i.e. the solution of x = cos x (about 0.7391)
g′(x)how strongly g stretches errors; |g′| < 1 means each round shrinks the distance to x*

It solves equations like x = cos x that cannot be rearranged algebraically. It only works if |g′| < 1 near the root; if it is bigger than 1 the guesses fly apart. Trig is always in radians.

  1. x1 = cos(1) = 0.540302.
  2. x2 = cos(0.540302) = 0.857553.
  3. x3 = cos(0.857553) = 0.654290 ⇒ 0.6543.

What it means: try it on a calculator in radian mode — type 1, then keep pressing cos. The display zig-zags 0.5403, 0.8576, 0.6543, 0.7935, 0.7014, … and slowly settles at 0.7391. It alternates above and below because g′ = −sin x is negative, and the swings shrink because |sin 0.7391| = 0.674 < 1. After three rounds you are still 0.085 away, so x3 is an iterate, not the root.

Common mistakes: degree mode (cos 1° = 0.9998 gives nonsense); rounding x1 to 0.54 early; stopping at x2 (or going to x4) by miscounting; treating the starting guess as one of the iterations.

Write this down — Tutorial 8

  • Newton divided differences: f[xi,xj] = (fj−fi)/(xj−xi) (a slope); f[x0,x1,x2] = (f[x1,x2]−f[x0,x1])/(x2−x0) (change in slope). Then p(x) = f[x0] + f[x0,x1](x−x0) + f[x0,x1,x2](x−x0)(x−x1). Valid for any distinct nodes; the last denominator uses the two outer nodes.
  • Interpolation error bound: |f(x)−p(x)| ≤ M/(n+1)! · |∏(x−xi)|, where M = max|f(n+1)| over the interval. Means: a guaranteed worst case, not the true error. Take the MAX of the derivative; (n+1)! = (number of nodes)!.
  • Fixed-point iteration: xn+1 = g(xn) solves x = g(x). Converges if |g′| < 1 near the root; if |g′| > 1 it diverges. x0 is the start, x3 is the third application.
  • Trap: trig in radians (calculator mode!), and keep 6 d.p. in intermediate values.

📘 Tutorial 9 — numerical ODEs (Euler, Heun, RK4)

Q4 · Tut 9

MCQ. The global error of Euler's method with step h is: (A) O(h)   (B) O(h²)   (C) O(h³)   (D) O(h&sup4;).

Try it yourself first, then reveal the full solution
Answer: (A)

What it’s asking: If you halve Euler’s step size h, how does the final error (after walking all the way to the target x) shrink? That is the “order” of the method.

Steps needed: (1) find the error made in one step (local); (2) count how many steps it takes to reach the target; (3) multiply to get the total (global) error.

Local errorthe mistake made in a single hop, assuming you started that hop exactly on the true curve
Global errorthe mistake left at the end, after the local mistakes of all hops have piled up
Eulerlocal O(h²), global O(h) — halve h, error halves
Heunlocal O(h³), global O(h²) — halve h, error ÷4
RK4local O(h&sup5;), global O(h&sup4;) — halve h, error ÷16

Why it matters: the order tells you how much accuracy you buy by shrinking h. Valid for smooth f; the constants hidden in O(·) depend on the problem.

Why (A) is right: Euler keeps y + h·y′ and drops the h²/2·y″ term of the Taylor series, so each hop is off by about h². To cross a fixed interval of length L you need L/h hops, so total error ≈ (L/h) × h² = L·h, which is O(h). Think of it as a small stumble on every step: the stumbles get smaller with h, but there are more of them, so you lose one power of h.

Why the others are wrong:

  • (B) O(h²) is Euler’s local error (or Heun’s global) — the classic trap of quoting the per-step error.
  • (C) O(h³) is Heun’s local error, a method one level up.
  • (D) O(h&sup4;) is RK4’s global error, two levels up.

Common mistake: remembering “order = exponent in the Taylor remainder” and forgetting that the remainder is per step; global is always one power lower.

Q5 · Tut 9

y′=x+y, y(0)=1, h=0.1. Euler's method: find y(0.2) (4 d.p.).

Try it yourself first, then reveal the full solution
Answer: 1.2200

What it’s asking: You do not have a formula for y, only a rule for its slope: at any point (x, y) the curve is climbing at y′ = x + y. Starting at (0, 1), take two hops of width 0.1 to estimate y at x = 0.2.

Steps needed: (1) compute the slope at the current point; (2) hop: new y = old y + h × slope; (3) move x forward by h; (4) repeat once more.

yn+1 = yn + h·f(xn, yn)     xn+1 = xn + h
hstep size = how far we hop along x each time (0.1)
f(x,y)the slope of the solution curve at the current point, handed to us by the ODE: here x + y
h·frise = slope × run, the amount y goes up in this hop
(xn,yn)where we are standing now
AnalogyWalking over a hill with your eyes closed, feeling only the slope under your feet right now. You walk 0.1 in that direction, re-feel the slope, walk again. If the hill is curving upward, you always step along the old, too-flat direction and fall a bit short.

It estimates y when no formula can be found. Needs an initial value; smaller h gives less drift.

  1. Hop 1 from (0, 1): slope f(0,1) = 0 + 1 = 1, so y1 = 1 + 0.1(1) = 1.100000 at x = 0.1.
  2. Hop 2 from (0.1, 1.1): slope f(0.1,1.1) = 0.1 + 1.1 = 1.2, so y2 = 1.1 + 0.1(1.2) = 1.220000 ⇒ 1.2200.

What it means: the exact solution is y = 2ex − x − 1, so y(0.2) = 1.242806. Euler is 0.0228 low (1.8%) because the true curve bends upward while each hop follows a straight, too-flat tangent.

Common mistakes: using the new x with the old y (or vice versa) when computing the slope; forgetting to update x after each hop; adding the slope without multiplying by h.

Q6 · Tut 9

Same equation. Heun's (improved Euler) method: y(0.2) (4 d.p.).

Try it yourself first, then reveal the full solution
Answer: 1.2421

What it’s asking: Same ODE and same two hops of 0.1, but this time each hop uses the average of the slope at its start and the slope at its (predicted) end, which follows the curve’s bend better.

Steps needed (each hop): (1) slope at the start; (2) predict the end value with an Euler hop; (3) slope at that predicted end; (4) average the two slopes and hop with the average.

y* = yn + h·f(xn, yn)   |   yn+1 = yn + (h/2)[ f(xn, yn) + f(xn+1, y*) ]
y*the predictor: a rough Euler guess of y at the end of the hop (a stepping stone, not the answer)
f(xn,yn)slope at the start of the hop
f(xn+1,y*)slope at the end of the hop: x is the next x and y is the predicted y
(h/2)[…]h times the average of the two slopes
AnalogyEstimating a car trip over the next minute. Euler: “I’m doing 60 km/h now, so 1 km.” Heun: “I’m doing 60 now and I’ll peek ahead — I’d be at about 80 by the end — so average 70, giving 1.17 km.” Peeking ahead catches the speed change.

It is more accurate than Euler for the same h because it cancels most of Euler’s drift. It costs two slope evaluations per hop.

  1. Hop 1 (x: 0 → 0.1, y = 1): start slope 0 + 1 = 1; y* = 1 + 0.1(1) = 1.1; end slope f(0.1, 1.1) = 1.2; y1 = 1 + 0.05(1 + 1.2) = 1.110000.
  2. Hop 2 (x: 0.1 → 0.2, y = 1.11): start slope 0.1 + 1.11 = 1.21; y* = 1.11 + 0.1(1.21) = 1.231; end slope f(0.2, 1.231) = 1.431; y2 = 1.11 + 0.05(1.21 + 1.431) = 1.11 + 0.13205 = 1.24205 ⇒ 1.2421 (the exact value 1.24205 sits on a tie and rounds up).

What it means: exact y(0.2) = 1.242806, Euler gave 1.2200, Heun gives 1.2421. Heun’s error (0.0008) is about 30 times smaller than Euler’s (0.0228) with the same step size, because it is second order (global error O(h²)) while Euler is only first order.

Common mistakes: using yn instead of y* in the end slope; using xn instead of xn+1 there; averaging the y-values instead of the slopes; reporting the predictor y* as the answer.

Q7 · Tut 9

y′=−2y, y(0)=1. One RK4 step with h=0.2: y(0.2) (4 d.p.).

Try it yourself first, then reveal the full solution
Answer: 0.6704

What it’s asking: Take ONE big hop (h = 0.2) for y′ = −2y using the fourth-order Runge–Kutta recipe, which samples the slope four times per hop.

Steps needed: (1) k1: slope at the start; (2) k2: slope at the midpoint using k1; (3) k3: slope at the midpoint again using k2; (4) k4: slope at the end using k3; (5) weighted average.

yn+1 = yn + (h/6)(k1 + 2k2 + 2k3 + k4)
k1f(xn, yn): slope at the start
k2f(xn+h/2, yn+(h/2)k1): slope at the midpoint, reached using k1
k3f(xn+h/2, yn+(h/2)k2): slope at the midpoint again, reached using the better k2
k4f(xn+h, yn+h·k3): slope at the end of the hop
1,2,2,1 /6weights: midpoints count double because they are the most trustworthy; the weights add to 6

It is Heun’s “peek ahead, then average” idea done four times, giving global error O(h4). In week 8’s notation a = h·k1, b = h·k2, etc. Here f depends only on y, so x is not needed.

  1. y0 = 1, h = 0.2, h/2 = 0.1. k1 = −2(1) = −2.
  2. k2 = −2(1 + 0.1·(−2)) = −2(0.8) = −1.6.
  3. k3 = −2(1 + 0.1·(−1.6)) = −2(0.84) = −1.68.
  4. k4 = −2(1 + 0.2·(−1.68)) = −2(0.664) = −1.328.
  5. Sum: −2 − 3.2 − 3.36 − 1.328 = −9.888; y1 = 1 + (0.2/6)(−9.888) = 1 − 0.3296 = 0.6704.

What it means: the exact answer is e−0.4 = 0.670320, so one RK4 hop is within 0.0001. For the same single hop, Euler gives 0.6000 and Heun 0.6800. (0.6704 vs 0.6703 is normal: RK4 is very accurate, not exact.)

Common mistakes: forgetting the doubles on k2 and k3; dividing by 4 instead of 6; using the full h instead of h/2 inside k2, k3; reusing k1 instead of k2 when building k3.

Write this down — Tutorial 9

  • Euler: yn+1 = yn + h·f(xn,yn). Walk along the slope you feel now. Global error O(h).
  • Heun (improved Euler): y* = yn + h·f(xn,yn); yn+1 = yn + (h/2)[f(xn,yn) + f(xn+1,y*)]. Average of start and predicted-end slopes. Global error O(h²). The end slope uses the NEW x and the PREDICTED y.
  • RK4: yn+1 = yn + (h/6)(k1+2k2+2k3+k4), where k2, k3 are slopes at the midpoint (step h/2) and k4 at the end (step h). Global error O(h4).
  • Local vs global: local error is per step; there are about 1/h steps, so global is one power of h lower. Halving h divides the error by 2 (Euler), 4 (Heun), 16 (RK4).
  • Trap: always update x as well as y, and evaluate f at the right (x, y) pair.

📘 Tutorial 10 — Laplace transforms & inverse transforms

Q8 · Tut 10

F(s)=L{t²e−3tu(t)}. Evaluate F(2) (4 d.p.).

Try it yourself first, then reveal the full solution
Answer: 0.0160

What it’s asking: Find the Laplace transform of t² multiplied by a decaying exponential, then plug s = 2 into the resulting formula.

Steps needed: (1) transform the plain t²; (2) apply the s-shift rule for the e−3t factor; (3) substitute s = 2.

L{tn} = n!/sn+1   |   L{e−atf(t)} = F(s + a)
f(t)the plain function without the exponential: here t²
F(s)its transform, 2!/s³ = 2/s³
athe decay rate in e−at: here 3
F(s+a)replace every s in F by s + 3: multiplying by e−3t slides the whole transform 3 units to the left
u(t)just says the function is switched on at t = 0 (every Laplace function is)

The s-shift rule only applies when the exponential multiplies the WHOLE function of t. F(2) is simply the value of the transform formula at s = 2 (the integral converges for s > −3, so s = 2 is fine).

  1. L{t²} = 2/s³.
  2. Shift: F(s) = 2/(s + 3)³.
  3. F(2) = 2/5³ = 2/125 = 0.0160.

Common mistakes: shifting the wrong way (s − 3 gives 2/(−1)³ = −2, a decaying exponential shifts to s + 3); multiplying transforms (1/(s+3) × 2/s³ = 0.05) — a product in t is NOT a product in s; dropping the 2 from 2!, which gives 0.0080.

Q9 · Tut 10

F(s)=L{(t−2)u(t−2)}. Evaluate F(1) (4 d.p.).

Try it yourself first, then reveal the full solution
Answer: 0.1353

What it’s asking: The function (t−2)u(t−2) is a ramp that stays at 0 until t = 2 and then starts climbing. Find its transform and evaluate it at s = 1.

Steps needed: (1) identify the un-delayed function g(t) = t; (2) transform it; (3) multiply by the delay factor e−2s; (4) set s = 1.

L{ g(t−a) u(t−a) } = e−as G(s)
athe delay: how many seconds late the signal starts (a = 2)
u(t−a)the switch: 0 before t = a, 1 after
g(t)the shape before delaying (here the ramp g(t) = t)
G(s)its transform: 1/s²
e−aswhat a delay of a looks like in the s-domain

The delay rule needs the function written as g(t−a)u(t−a): the same t−a must appear inside g and in the switch. Here it already does.

  1. g(t) = t ⇒ G(s) = 1/s².
  2. F(s) = e−2s/s².
  3. F(1) = e−2/1 = 0.135335 ⇒ 0.1353.

What it means: a delay in time becomes a factor e−as in the s-domain; the larger s is, the more it is damped.

Common mistakes: forgetting e−2s (gives 1.0000); using e+2s (7.3891); applying the rule to t u(t−2) — that is NOT in shifted form (write t = (t−2) + 2 first, giving e−2s(1/s² + 2/s)).

Q10 · Tut 10

MCQ. L{ sin(t−2) u(t−2) } = (A) e−2s/(s²+1)   (B) e−2s(cos 2 ·1+…)/(s²+1)   (C) 1/(s²+1)   (D) e2s/(s²+1).

Try it yourself first, then reveal the full solution
Answer: (A)

What it’s asking: Pick the right transform for a sine wave that starts late: it is 0 until t = 2, then runs as sin(t−2).

Steps needed: (1) check whether the function already has the form g(t−a)u(t−a); (2) if yes, transform g and multiply by e−as.

L{ g(t−a) u(t−a) } = e−as G(s)   with g = sin, a = 2, G(s) = 1/(s²+1)
g(t)the original wave, sin t
G(s)L{sin t} = 1/(s²+1)
a = 2the delay; the same 2 appears in both sin(t−2) and u(t−2), so the pattern matches exactly

The delay rule is valid only when the shift appears inside the function AND in the step. When it matches, no trig identity is needed.

Why (A) is right: sin(t−2)u(t−2) = g(t−2)u(t−2) with g = sin, so the transform is e−2s/(s²+1).

Why the others are wrong:

  • (B) as printed is garbled, but the cos 2 pieces point to the compound-angle trap: expanding sin(t−2) = sin t cos 2 − cos t sin 2 and transforming term by term. That expansion is only needed when the step is NOT shifted, i.e. L{sin(t−2)u(t)} = (cos 2 − s sin 2)/(s²+1). Here the shifted step does the work, so (B) over-complicates and is wrong.
  • (C) 1/(s²+1) forgets the delay: that is the transform of the undelayed sin t.
  • (D) e2s has the wrong sign: a delay is e−as; e+2s would be an advance and blows up for large s.

Common mistakes: missing the delay factor; flipping the sign of the exponent; expanding with trig identities when the problem is already in shifted form.

Q11 · Tut 10

g(t) = u(t) + u(t−2) − 2u(t−3). Evaluate G(s) at s=1 (4 d.p.).

Try it yourself first, then reveal the full solution
Answer: 1.0358

What it’s asking: g(t) is built from three on/off switches. Transform each switch, add them up, then plug in s = 1.

Steps needed: (1) transform each u(t−a) with the delay rule; (2) keep the constant multiples (linearity); (3) combine into one fraction over s; (4) substitute s = 1.

L{ u(t−a) } = e−as/s
u(t−a)a switch that is 0 until t = a and 1 afterwards
1/sL{u(t)}: the transform of a switch turned on at t = 0
e−asthe delay factor for turning it on at t = a instead
−2a constant multiplier; it just comes along for the ride (linearity)

Valid for any piecewise-constant signal: write it as a sum of switches. Linearity (L{af + bg} = aF + bG) lets you transform each term separately.

  1. u(t) → 1/s; u(t−2) → e−2s/s; −2u(t−3) → −2e−3s/s.
  2. G(s) = (1 + e−2s − 2e−3s)/s.
  3. At s = 1: e−2 = 0.135335; 2e−3 = 0.099574.
  4. G(1) = 1 + 0.135335 − 0.099574 = 1.035761 ⇒ 1.0358.

What it means: g(t) is a staircase: 1 for 0 ≤ t < 2, then 2 for 2 ≤ t < 3, then back to 0 (1 + 1 − 2 = 0) for t ≥ 3.

Common mistakes: forgetting to divide the delayed terms by s; combining −2e−3s as e−6s; using e−3 = 0.0498 without the factor 2.

Q12 · Tut 10

f(t)=L−1{5/[s(s+5)]}. Find f(0.5) (4 d.p.).

Try it yourself first, then reveal the full solution
Answer: 0.9179

What it’s asking: Go from the s-domain back to time: find the function f(t) whose transform is 5/[s(s+5)], then evaluate at t = 0.5.

Steps needed: (1) split the fraction into simple pieces (partial fractions); (2) invert each piece from the table; (3) plug in t = 0.5.

5/[s(s+5)] = A/s + B/(s+5)
Acover-up: hide the factor s, set s = 0 in what remains: 5/(0+5) = 1
Bhide (s+5), set s = −5: 5/(−5) = −1
1/sinverts to 1 (a constant)
1/(s+5)inverts to e−5t (a decay with rate 5)

Partial fractions work because the table only knows simple pieces like 1/s and 1/(s+a). The cover-up shortcut is valid for distinct, non-repeated real poles.

  1. 5/[s(s+5)] = 1/s − 1/(s+5). Check: [(s+5) − s]/[s(s+5)] = 5/[s(s+5)] ✓.
  2. f(t) = 1 − e−5t.
  3. f(0.5) = 1 − e−2.5 = 1 − 0.082085 = 0.917915 ⇒ 0.9179.

What it means: f rises from 0 towards 1, like a first-order system filling up with time constant 1/5 = 0.2 s. At t = 0.5 s (2.5 time constants) it is 91.8% of the way there.

Q15 · Tut 11

y′+3y=u(t), y(0)=2. Find y(1) (4 d.p.).

Try it yourself first, then reveal the full solution
Answer: 0.4163

What it’s asking: Solve y′ + 3y = u(t) with y(0) = 2 (a system that is switched from rest at 2 and hit by a step input of 1), then read y at t = 1.

AnalogyLaplace is a unit conversion. A recipe is awkward in some units, so you convert to cups, do the simple arithmetic, then convert back. Laplace converts a calculus problem (differential equation) into algebra, you solve the algebra, then convert back to time.

Steps needed: (1) transform the whole ODE; (2) solve algebraically for Y(s); (3) partial fractions; (4) invert to y(t); (5) evaluate at t = 1.

L{y′} = sY(s) − y(0)   |   L{u(t)} = 1/s
Y(s)the transform of the unknown y(t)
sY − y(0)how a derivative looks in the s-domain: multiply by s, then subtract the starting value, so the initial condition is built in automatically
1/sthe step input

Valid for constant-coefficient linear ODEs. The initial conditions go in at the first step, so the final answer already satisfies them.

  1. sY − 2 + 3Y = 1/s.
  2. (s+3)Y = 2 + 1/s = (2s+1)/s ⇒ Y = (2s+1)/[s(s+3)].
  3. Cover-up: A (s=0) = 1/3; B (s=−3) = (−6+1)/(−3) = 5/3. So Y = (1/3)/s + (5/3)/(s+3).
  4. y(t) = 1/3 + (5/3)e−3t.
  5. y(1) = 0.333333 + 1.666667(0.049787) = 0.333333 + 0.082978 = 0.416312 ⇒ 0.4163.

Check & meaning: y(0) = 1/3 + 5/3 = 2 ✓, and y′ + 3y = −5e−3t + 1 + 5e−3t = 1 ✓. The solution starts at 2 and relaxes towards 1/3, where 3y = 1 balances the input.

Common mistakes: dropping the −y(0) term; forgetting that the step contributes 1/s; arithmetic sign slip in B.

Q16 · Tut 11

y″−2y′−3y=u(t), y(0)=y′(0)=0. Find y(1) (4 d.p.).

Try it yourself first, then reveal the full solution
Answer: 1.4324

What it’s asking: Same Laplace method as Q15, but with a second derivative and zero starting conditions: solve y″ − 2y′ − 3y = u(t) and find y(1).

Steps needed: (1) transform using the second-derivative rule; (2) factor the quadratic in s; (3) three-term partial fractions; (4) invert; (5) evaluate.

L{y″} = s²Y − s·y(0) − y′(0)   |   L{y′} = sY − y(0)
y(0), y′(0)the starting position and velocity; both are 0 here so those terms vanish
s²−2s−3the “characteristic polynomial”: one s for each derivative order
A, B, Cthe coefficients of 1/s, 1/(s−3), 1/(s+1) in the partial fractions

Gives the whole solution in one pass — forced response and natural response together. The roots 3 and −1 of the characteristic polynomial decide the behaviour.

  1. (s² − 2s − 3)Y = 1/s, and s² − 2s − 3 = (s−3)(s+1).
  2. Y = 1/[s(s−3)(s+1)] = A/s + B/(s−3) + C/(s+1).
  3. Cover-up: A (s=0) = 1/[(−3)(1)] = −1/3; B (s=3) = 1/[3·4] = 1/12; C (s=−1) = 1/[(−1)(−4)] = 1/4.
  4. y(t) = −1/3 + (1/12)e3t + (1/4)e−t.
  5. y(1): e3/12 = 1.673795; e−1/4 = 0.091970; total −0.333333 + 1.673795 + 0.091970 = 1.432431 ⇒ 1.4324.

Check & meaning: y(0) = −1/3 + 1/12 + 1/4 = 0 ✓ and y′(0) = 3/12 − 1/4 = 0 ✓. The e3t term comes from the pole at s = 3 in the right half-plane, so this system is unstable and y grows without bound; −1/3 is the level where −3y = 1.

Common mistakes: mis-factoring (s+3)(s−1) = s²+2s−3 instead of (s−3)(s+1); forgetting the 2 in the 2sY term; wrong sign in a cover-up.

Q17 · Tut 11

MCQ. y′−2y=u(t), y(0)=1 is: (A) stable, bounded input   (B) unstable, because of the pole at s=2 of the system itself   (C) unstable, because the input is a step   (D) stable because the output tends to a constant.

Try it yourself first, then reveal the full solution
Answer: (B)

What it’s asking: Is the system itself stable — and what is to blame if not: the system or the step input?

AnalogyA ball in a bowl, nudged, rolls around and settles at the bottom: stable (poles in the left half-plane). A ball balanced on top of a hill, nudged, rolls away forever: unstable (a pole in the right half-plane). Stability is a property of the landscape (the system), not of how hard or how long you push it.

Steps needed: (1) solve for Y(s); (2) list the poles; (3) split them into “system” poles and “input” poles; (4) judge the system poles by the sign of their real part.

polea value of s that makes the denominator zero; each pole p contributes a term ept to the time response
s = 2from (s−2), the system’s own left-hand side: e2t, which grows
s = 0from the step input 1/s: a constant, bounded

A system is stable only if ALL its own poles have negative real parts. Input poles do not decide stability.

  1. (s−2)Y − 1 = 1/s ⇒ Y = (s+1)/[s(s−2)].
  2. Partial fractions: Y = (−1/2)/s + (3/2)/(s−2), so y(t) = −1/2 + (3/2)e2t.
  3. The e2t term explodes however small the input is.

Why (B) is right: the pole at s = 2 belongs to the system, so it is unstable.

Why the others are wrong:

  • (A) Bounded input does not guarantee bounded output unless the system is stable; the bounded step is hitting an unstable system.
  • (C) The step is bounded and only contributes the harmless pole at 0; blaming the input confuses cause with system.
  • (D) The output does not tend to a constant: it is dominated by (3/2)e2t.

Common mistake: calling a system stable because the input is bounded or because it looks “steady” at one instant.

Q22 · Tut 11

(u∗u)(t) where u is the unit step. Find its value at t=3.

Try it yourself first, then reveal the full solution
Answer: 3

What it’s asking: Convolve a unit step with itself and read the result at t = 3.

AnalogyConvolution smears one signal with another. Flip one function, slide it across the other, and at each position record the overlapping area. For two steps the overlap grows steadily as you slide, like water pouring in at a constant rate: the level (running total) rises in a straight line.

Steps needed: (1) write the convolution integral and use the step’s values; or (2) use the convolution theorem with transforms. Do both as a check.

(f∗g)(t) = ∫0t f(τ) g(t−τ) dτ   |   L{f∗g} = F(s)·G(s)
τdummy sliding variable: which moment of f we are looking at
g(t−τ)g flipped and shifted, so it lines up with f
u(τ), u(t−τ)both equal 1 for 0 < τ < t

Convolution gives the output of a linear system for any input (input ∗ impulse response), and in the s-domain it becomes plain multiplication.

  1. Integral: (u∗u)(t) = ∫0t (1)(1) dτ = t.
  2. Laplace: (1/s)(1/s) = 1/s² ↔ t u(t). Same result.
  3. At t = 3 the value is 3.

What it means: integrating a constant step gives a ramp; the result at t is the elapsed time.

Common mistakes: treating convolution like ordinary multiplication (u·u = u would give 1); inverting 1/s² as t² (that is 2/s³); ignoring the limits 0 to t.

Write this down — Tutorial 11

  • Solving ODEs by Laplace: L{y′} = sY−y(0); L{y″} = s²Y−sy(0)−y′(0). Transform, solve for Y, partial fractions, invert. Initial conditions go in at step 1.
  • Stability: poles are the roots of the system’s denominator. Stable iff ALL have negative real part (left half-plane). A pole at +p gives ept, which grows. Input poles (e.g. 0 from a step) do not decide stability.
  • Final-value theorem: y(∞) = lims→0 sY(s); for a unit step, = H(0). Valid only if the system is stable.
  • Impulse response: h(t) = L−1{H(s)}, since an impulse has transform 1. Fingerprint of the system.
  • Convolution: (f∗g)(t) = ∫0t f(τ)g(t−τ)dτ, and L{f∗g} = F·G. Output = input ∗ impulse response.
  • RC circuit: i(t) = (V/R)e−t/RC for a step source and an uncharged capacitor; τ = RC.
